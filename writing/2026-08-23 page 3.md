Taking inspiration from the build tools used with programming languages, we treat an incrementally processed corpus as a dependency graph. A tool that requires 16k audio files declares those as a dependency, so the pipeline needs to have a component that provides this function. We intentionally do not enforce a particular tool for a purpose, as user preference is key. Temporary files created as intermediate processing steps are treated as ephemeral: if a second component also depends on the same transformation component, the files created by the first run are reused if still available, or recreated if not.

Acquisition nodes are typically flagged as start nodes, but need not be: we consider the need to work with data that was processed outside of a declared pipeline important enough that it is possible to bring in external data at any stage of a pipeline; where appropriate, these are flagged as manual transformations—this simplifies the graph, while giving pointers to users where external actions must be taken.
