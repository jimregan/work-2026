
We take as inspiration the build tool for a programming language: a typical build tool is specified in terms of dependencies, and transformation steps to realise the build for a particular piece of the system.

In the most simple case, a component that depends on functionality provided by others adds those as dependencies, meaning that they must be compiled (or otherwise processed) before that can be compiled. These in turn can have their own dependencies. The build tool then creates a dependency graph so that each of the components can be compiled in the correct order to satisfy their dependencies.

Although compilation is the typical transformation, build tools are usually tool-agnostic, which allows maximum flexibility. For example: a protocol definition is usually specified in code-neutral terms, which must first be converted into a concrete set of declarations, before being compiled.

The UNIX `make` tool is one of the best known (and simplest) build tools. A `makefile` is a set of targets to be produced, with a list of targets it depends on, followed by a set of commands to be executed to create the desired targets.
